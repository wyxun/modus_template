# Class / Driver 模板配置边界

## Class 与 Driver 的职责

`template_class_t` 是 MODUS 注册对象和业务编排者：它保存 Class 自身状态，并按值拥有一个 `template_driver_t`。Class 初始化时接收配置并传给子 Driver；随后在 `Run()` 中推进前台流程、读取 Driver 状态并把子模块错误收敛到 Class 的 `ERROR` 状态。具体产品可组合多个 Driver，或通过类型化接口调用算法模块；父 Class 负责决定何时调用子模块和如何处理结果。

`template_driver_t` 是可独立实例化的功能对象：它拥有每实例运行状态、外部依赖绑定、服务计时、PT 游标和故障记录。Driver 负责维护自己的状态约束并通过操作 API 执行初始化、服务、停止、复位和状态查询；父 Class 不应直接改写 Driver 的运行成员。所有可变运行数据属于对象实例，不藏在 `.c` 的静态变量中。

`template_class_cfg_t` 按值包含子 Driver 的 `template_driver_cfg_t`，用于把外部输入交给 `template_driver_Init()`；`template_class_t` 则按值拥有 `template_driver_t`。`template_driver_t` 不包含完整的 `template_driver_cfg_t`；初始化后不再依赖原始 cfg 对象，只保留必要的依赖绑定和执行参数。

| 阶段 | 数据 | 职责 |
| --- | --- | --- |
| 配置边界 | `template_driver_cfg_t` | 用开发者熟悉、含义明确且带单位的领域量描述需求，并提供外部依赖。时间、频率、角度、速度、电压等都应使用对应领域单位；不要要求调用者提供内部 tick、缩放计数或压缩编码。 |
| 初始化 | `template_driver_Init()` | 校验配置与依赖，将领域量换算、规范化或压缩为内部执行参数；当前示例把 Hz 换算为整数 tick，不可表示的输入直接报错。 |
| 执行 | `template_driver_t` | 只保存后续操作需要的依赖、`wPeriodTicks`、状态和计数；运行路径直接比较 tick。 |

当前示例用 tick 源频率 `wTickRateHz` 和期望更新频率 `wUpdateRateHz` 演示这条边界：tick 源为 1000 Hz、期望更新频率为 333 Hz 时，初始化把周期向上取整为 4 tick。量化后的实际频率不会高于请求值。配置频率不能为零，也不能高于 tick 源频率；周期超过半个 32 位计数范围时会被拒绝，以维持回绕比较的有效边界。这两个 Hz 字段只是本示例的领域配置，并不限定其他 Driver 必须采用频率配置。复制模板时，应按具体模块的领域语义定义配置字段，并按实际时钟源填写 tick 频率。

`wInitialValue` 只是通用采样示例的占位输入。具体 Driver 应把它改成有明确单位的物理量，或者在不需要初值时删除；运行对象只保留换算后确实会使用的字段。

对有单位或领域意义的常量、换算比例和边界值，应定义带语义的宏（例如 `FOC_NANOSECONDS_PER_SECOND`），并在使用处引用宏；不要在表达式中散布裸的具体数值。仅有清楚含义的语言常量（如 `0U`）可直接使用。

## 当前模板展示的能力

### Class 能力

- `Init()` 检查对象和配置，绑定每实例依赖，初始化子 Driver，再注册 MODUS 基类；失败时记录错误，并在适用路径请求 Driver 停止。
- `Run()` 使用对象持有的 PT 游标推进前台非阻塞流程；模板示例调用子 Driver 并将子 Driver 故障提升为 Class 错误。
- `Clock()` 是可选的短周期回调，转调 Driver 的 Clock 服务并检查错误状态，不用于放置阻塞业务流程。
- Class 与 Driver 分别拥有自己的状态和错误信息。Class 管业务状态与子模块错误，Driver 管服务状态、详细错误和故障位。

### Driver 能力

| API / 能力 | 模板示例行为 | 特化时的选择 |
| --- | --- | --- |
| `Init()` | 校验外部依赖及配置，转换执行参数，初始化依赖并进入 `IDLE`。 | 所有具体 Driver 都保留初始化和必要的校验；删除无关配置与依赖。 |
| `Run()` | 通过 PT 等待配置周期，采样并应用数据，单步返回进度。 | 仅在有前台非阻塞流程、校准或异步 I/O 时保留；纯 ISR 算法删除 PT 服务。 |
| `Start()` / `Stop()` | 控制服务状态；`Stop()` 调用依赖的安全停止操作并结束计时。 | 仅在模块确实具有启停语义时保留，并定义安全输出。 |
| `Reset()` | 先请求依赖停止，成功后清除 Driver 错误、故障位和 PT 游标。 | 按故障恢复语义实现；不能跳过安全停止条件。 |
| `GetStatus()` | 复制只读状态快照，含状态、最近错误、故障位、当前值和计时标志。 | 保留父 Class 必须读取的最小状态；不开放父对象直接改写内部成员。 |
| `Clock()` | 调用可选固定周期依赖回调并锁存错误。 | 仅用于短小、固定周期服务；不承载第二套前台流程。 |
| `IsrStep()` | 演示可选的短硬件 ISR 钩子。 | 实时算法应提供类型明确的 ISR API，直接消费初始化准备好的执行参数；避免 ISR 热路径上的通用函数指针分派、配置解析、单位换算、日志和阻塞操作。 |

`template_driver_hw_ops_t` 的 `sample/apply/stop/clock/isr` 都是能力示例，不是所有 Driver 的固定契约。按具体模块选择能力档位并删除未使用的 API。若 Driver 是算法模块，应以语义明确的输入、输出和类型化接口表达算法契约；`template_interface.h` 展示了用 C11 `_Generic` 在编译期选择算法实现的方式。

ISR 只消费已经校验、换算、压缩到对象中的执行参数，不应在每次中断中读取原始 `cfg`、校验配置或做 Hz 到计数的换算。当前 `template_driver_IsrStep()` 仅演示可选硬件回调；具体实时算法应定义类型化入口，并把其所需的执行参数在初始化阶段准备好。前台 `Run()` 示例已经直接使用 `wPeriodTicks` 比较经过的 tick。

## `template_interface.h`：算法族的类型化接口

`template_interface.h` 不是另一个 Driver 基类，也不创建对象、保存运行状态或注册全局实现。它提供一个最小的接口结果枚举，以及 `TEMPLATE_INTERFACE_SELECT()` 宏：调用点提供具体对象指针类型与对应函数，C11 `_Generic` 在编译期选出函数，随后仍由编译器检查该函数的参数类型。

当同一调用位置要支持一组语义相同、具体类型不同的算法对象时，可以用这种方式组织接口，例如 SMO、Flux 或 EKF 的 ISR 计算入口。接口族的输入、输出、具体函数和类型映射应放在相应算法族或应用适配层中；不要把具体算法类型清单塞进通用 Class/Driver 模板。

选择方式取决于绑定时机：构建时已知算法类型、且调用处需要直接的类型化调用时，使用 `_Generic`；实现需在运行时由配置选择时，才使用 `ops/context`。同一调用链不要同时叠加两套分派。硬实时算法路径应传递采样值和已准备好的执行参数，避免通过通用 Driver 回调引入运行时函数指针分派。
