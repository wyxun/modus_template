# Identify 标幺边界整理

> 本文记录 PU 边界整理时的版本；后续 Rs/Ld 的 dq 输入和零位门槛已由 [R/L 无编码器辨识](2026-10-09-identify-stationary-boundary.md) 替换为固定 αβ 会话。当前契约以 [架构文档](foc-architecture.md) 为准。

用户已确认实施。基于现有未提交改动继续整理，不提交或覆盖其他工作。

## 设计与变化

| 边界 | 调整前 | 调整后 | 理由 |
|---|---|---|---|
| ISR 输入 | 分散的 Id/Iq/Vd、母线 mV、Motor 指针 | Rs/Ld 各自固定的独立采样类型；电流 dq pu、模型 D 轴电压 pu、有效性/限幅，Ld 另有速度 pu | 新增磁链只增加自己的类型与入口，不扩张或改变旧输入语义 |
| ISR 输出 | 辨识直接修改 Motor、停止 PWM | 电压请求和立即中止请求，由 App 同一 ISR 提交给 Motor | 算法拥有辨识状态，Motor 拥有控制与安全输出 |
| 母线 ADC 边界 | App 读取原始码、换算 mV 并除以 Motor 电压基值 | `motor_SampleDcBusPuIsr()` 在 Motor 内做板级标定、范围检查和 PU 归一化 | ADC 物理输入与电压基值的转换归 Motor；App 只编排数据流 |
| 电压模型 | R 最终使用宏电压差；L 使用母线 mV 乘宏幅值 | 上一控制区间占空比与实时母线采样重构，转换到本拍 dq 坐标 | 捕获实际母线变化，避免命令与生效区间混用 |
| 数值计算 | R PU 后转换 mΩ；L 混合 mV/mA/mΩ | R/L 输入、模型参数、结果均为 PU，固定后端局部宽累加 | 结果可被控制算法消费，不做物理单位往返 |
| 物理显示 | 状态长期保存 mΩ/µH | 初始化推导显示尺度，`identify_ResultToPhysical()` 前台按需生成 mΩ/µH | 物理量停留在配置与显示边界 |
| 结果出口 | App 分别轮询 Rs/Ld getter | `identify_Run()` 一次返回带操作标签的 PU 结果 | 调度层只推进当前算法，Rs/Ld 仍独立启动、计算和采样 |
| Ld 状态 | 注入配置、采样累加、流程/结果平铺 | 实例内组合 `tPlan`、`tCapture`、流程/结果 | 外层 10 个成员；计划 12、采样 16 个成员，不引入共享 static 可变状态 |

`Rbase = Ubase/Ibase`，`Lbase = Ubase/(ωbase Ibase)`，
`Ts_pu = ωbase/F_HF`，`ωbase = 2π fbase`。

R：`r_pu = Δu_model_pu / Δi_pu`，检查非零差分及电压/电流同号。
L：`l_pu = (u_mean_pu - r_pu i_mean_pu) × (N-1)Ts_pu / Δi_pu`，
正负半周分别估计并平均。成功的 R 结果作为后续 L 使用的电阻 PU。

电压重构：`uα = (2du-dv-dw)/3 × vbus_pu`，
`uβ = (dv-dw)/√3 × vbus_pu`，在本拍电角度转为 dq。
占空比取提交新 PWM 前的上一份成功输出；母线采样代表当前采样时刻。
这是理想逆变器模型，尚不补偿死区、器件压降与 PWM 硬件生效延迟。
ADC/PWM 真实拍关系仍需台架确认，不能称作端电压实测。

仅 ISR 算法接口解除 Motor 依赖。前台启停、零位要求仍使用既有 Motor
生命周期；本次不实现无编码器辨识启动。后续新辨识增加自身状态与算法，
沿用纯输入/请求输出，不添加父指针、回调或覆盖全控制链的大快照。

## 验证结果

- Rs 两档分别使用 10.8 V、13.2 V 的物理电流/电压输入，FLOAT/FIXED 还原约 2.55 Ω；结果 API 返回 PU，显示转换单独校验。原先不使用采集电压的实现确实导致这组回归失败。
- Ld 用独立物理 RL 指数瞬态作参照，R=1 Ω、L=860 µH，在 10.8 V 和 15 V 母线下分别估算，FLOAT/FIXED 显示误差均在 ±5 µH 内。原有小差分、斜率反号、PWM 限幅失败回归继续通过。
- 电压重构覆盖不同母线 PU、0/90° 坐标、零电压、非法占空比与母线；实例基值隔离、类型错误入口不串扰、缺失采样锁存错误通过。
- Motor 母线采样 API 在 FLOAT/FIXED 下覆盖板级比例换算、无效 ADC 码、零电压基值和超范围母线；App 不再读取 ADC 或执行物理到 PU 的除法。
- App 前台/命令及 ISR 请求提交测试通过，覆盖正常电压提交、Motor 拒绝请求、母线归一化失败、控制步失败，同一 ISR 只中止一次。
- App 通过单一 `identify_Run()` 结果出口消费 Rs/Ld 的带标签 PU 结果；进行中或失败时输出标签为空，不再轮询两个 getter。
- 独立 Identify 契约、现有 FOC 模块边界、Motor alpha-beta/速度 PU/Break 回归通过。
- 使用 `.\make.bat TARGET_CHIP=stm32g431 SW_ROOT=D:/0_software` 完成 FLOAT debug-rel 构建；FIXED release 以独立构建目录验证。默认脚本工具链路径仍指向不存在的 `D:/software`，本次通过命令参数覆盖。
