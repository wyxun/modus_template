# 接管过渡阶段：四路速度诊断固件

本轮只修改波形观测及相关测试，未连接 MCU、烧录、复位或启动电机。SMO、Position、Motor 控制逻辑及保护门槛均未改动。直接执行 `.\make.bat auto` 即使用本配置，无附加参数。

## 为什么替换辅助通道

上一版两次都通过 4000 拍连续资格，分别在渐变第 23 和 308 拍发生 Position 故障。第二次采集完整，最高抽查 ISR 为 45.8706 μs，故障前反电势没有塌陷，最后成功拍的观测角相对强拖角约 -43.28°，接近 45° 门槛。

此前只有反电势和角度，离线计算的滑动速度不能代替固件实际输出的非重叠窗口速度，也不能准确恢复 Position 速度滤波历史。因此先直接观察两级已有速度，暂不调整算法或放宽门槛。

## 默认四路及含义

| 顺序 / 名称 | 来源 | 单位 |
|---|---|---|
| 1 `SMO_mT` | `tPosition.tEstimate.tElectricalAngle` | 电角圈数 [0,1)；无效为 -1 |
| 2 `SmoSpd` | `tPosition.tEstimate.qElectricalSpeedPu` | 实际发布的窗口速度，电速度 PU |
| 3 `FiltSpd` | `tPosition.tTracking.qObserverSpeedFilteredPu` | Position 现有滤波速度，电速度 PU |
| 4 `EncAbs` | 编码器现有缓存的绝对电角度 | 电角圈数 [0,1)；没有校零偏置修正 |

电速度基值仍为 400 电 Hz，0.4 pu 即 160 电 Hz。SMO 窗口仍为 20 个控制间隔、1 ms，未改系数和发布节奏。上述速度不是 CSV 后处理推算值。

速度探针仅在 RUNNING、PWM 开启、SMO 估计有效时输出。滤波速度还要求原有 `bObserverSpeedReady`。无效或未就绪统一输出 -2；正常的零速度、正反向和门槛外速度不会被平滑或钳制。

波形浮点值乘 1000 后转 int16，探针仅接受绝对值不超过 32 pu 的有限值，确保转换落在有符号 16 位范围；NaN、Inf 和超范围值输出 -2。1.2 pu 等门槛外但可传输的值仍保留，有助于辨认保护条件。-2 位于正常允许速度范围之外，不能将其换算成实际转速。

所有名字均不超过协议允许的 7 个字符，避免再次发生 Ealpha_mpu 被截断一类歧义。

## 对 20 kHz 实时路径的影响

本轮复用已有 `foc_debug_CaptureWaveform()`，只在接受到 10 kHz 波形采样时读取已有状态。两路速度替代两路反电势，总数仍为四路，暂存仍是原来的 16 字节，没有增加历史缓冲、实例成员、公共函数或 ISR 日志。

新增操作为状态判断、读取两个 float、绝对值/范围比较和写入原有暂存；没有新增三角函数、除法或速度滤波计算。编码器参考仍只读缓存，没有新增 ISR I2C。目标反汇编中的范围检查为 `vabs.f32`；回调调用仍只有原有时间、编码器缓存和角度转换函数，无新增调用。

控制仍为 20 kHz、每拍 50 μs，波形仍为 10 kHz。SMO / Position 的计算顺序、采样与 PWM 拍关系、连续资格、45° 角差门槛及速度门槛全部不变。

注意：这些是静态开销与构建证据，不能证明新版 ISR 最大耗时。上一版最高抽查已达 45.87 μs，余量约 4.13 μs；本版必须重新测量，尤其关注渐变阶段，不得用平均耗时替代峰值。

## 观测时间和分辨率限制

现有 ISR 顺序为：Prepare → Position 选角 → 控制 → SMO / 速度滤波发布 → 波形采样。两路速度对应同一拍末尾发布的状态，Position 在下一拍使用它们，本轮没有为诊断改这个顺序。

20 kHz 控制而 10 kHz 采集，可能漏掉一拍持续 50 μs 的异常。如果速度刚发布后下一拍立即触发故障，而该发布拍没有被波形采到，故障后清零会使这份异常值不可见。不能据图上未见越界就认定对应条件没有触发。

本轮不为捕捉这一情况新增长期故障缓存或更改复位逻辑。先用现有四路排查持续速度偏差与角度漂移；如果仍不足以区分失败谓词，再依据采集结果决定最小的下一步观测。编码器绝对角存在固定零偏，不能直接把 SMO−EncAbs 当作资格检查中的 SMO−强拖角。

## 验证

1. 先补运行时通道测试，旧代码在缺少两路速度通道的数量断言处失败；加入实现后通过。
2. 使用相互不同的 0.465 / 0.395 pu 验证两个探针分别读取正确状态；改变为负值后立即更新，未复用旧数据。
3. 覆盖滤波未就绪、估计无效、PWM 关闭、IDLE / ALIGN / FAULT、NaN / ±Inf、±33 pu；均按各自条件输出无效标记。±33 pu 用例在仅检查有限值的实现上失败，补充传输范围检查后通过。
4. 验证正常门槛外 ±1.2 pu 保持原值，停机无效后的正常状态能够恢复，Observer Reset 后两路均无效。
5. 默认四路和 residual / bemf / current / speed 替代四路均通过；测试明确断言恰好四路、50,000 ns 控制周期和 10,000 Hz 波形。超过六路仍编译拒绝。
6. FLOAT / FIXED 应用、SMO 速度跨度、Position 接管测试通过；真实 App/Motor/Position/Core 八种组合及模块边界通过。
7. 本项目波形仅在 FLOAT 启用；FIXED 控制路径仍验证构建和回归，不宣称 FIXED 提供这些浮点波形通道。
8. C 82 字符行宽及 `git diff --check` 通过。测试运行器在预期的超过六路编译失败检查后明确退出 0，避免成功测试留下预期非零状态。未 stage / commit。

## 用户烧录后的短测

1. 在工程目录执行 `.\make.bat auto`，进入 RTT 后通知继续。此版本仍为 d 轴强拖→SMO 自动接管，不是编码器闭环。
2. 先确认 IDLE、PWM=0、无故障，读取并固定 AS5600 SF3 / CONF0300；核对四路名字，避免分析脚本仍沿用反电势列名。
3. 相同方向、空载、0.4 pu 下先做单次短测，采集约 9 秒。复用现有 motor status 和 ISR 计时读取，不添加 ISR 输出；峰值抽查接近预算时提前停机。采集结束后必须有明确停机收敛。
4. 检查样本序号、空行、非有限值、设备 drop 和 RTT full。只用完整记录作对比，不插值填洞。
5. 在仍为强拖 / 渐变时，对照 `SmoSpd` 与 [0.34,0.46]、`FiltSpd` 与 [0.36,0.44]；这些是目标 0.4 pu 下现有资格速度范围，不是新参数。若已进入 OBSERVER，应改用该阶段现有保持条件解释，不能继续套用强拖门槛。
6. 同步保留 phase / qualified / blend 及停机后的现有保留状态，区分速度偏差和相位衔接。若速度没有明显越界，不得据此盲目修改角差门槛；结合采样限制继续定位。

这份固件的目的仅是补齐两级实际速度证据，不代表 SMO 毛刺或接管故障已经修复。
