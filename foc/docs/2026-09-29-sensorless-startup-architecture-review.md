# 无编码器强拖启动与观测器接管审查

对比提交：`a17014088a53b96e7` → `9acf1bc32ca6be13f0`。参考[无编码器 I/f 启动与 SMO 接管计划](2026-09-26-sensorless-if-startup-smo-handoff-plan.md)、[现有 FOC 架构说明](foc-architecture.md)和[简化审查](2026-09-29-sensorless-startup-ponytail-review.md)。

本文依据代码做静态审查，没有运行构建、主机测试或带电实验。控制效果、阈值与执行时间仍需测量；不能把主机测试通过等同于无感接管已在电机上验证。

## 1. 总体判断

本次提交增加了 I/f 斜坡、无感对齐后连续运行、SMO 资格判断、角度交接和速度 PI 跟踪。`Motor Prepare → Position 选角 → Motor Control/PWM → Observer 更新` 的主链可以保留：Motor 负责采样及功率级，Position 产出唯一电角反馈，Observer 在 PWM 提交后更新供下一周期使用。

需要整理的是主链内部的重复状态和配置。旧定频轨迹与新斜坡轨迹并存；Motor 和 Position 分别计算强拖期限；接管参数在 App 与 Position 之间逐字段转抄。融合耗时和计划中的限幅资格判据还有未闭合的边界。这些问题不要求现在建立通用融合框架。

| 基线 `a170140` | 新提交 `9acf1bc` | 审查判断 |
|---|---|---|
| 固定频率强制角；Position 选 SENSOR 或 HARD_DRAG；SMO 影子运行。 | 增加 `motor_startup_t` 斜坡与无感启动入口。 | 斜坡是新需求；旧定频能力的去留需明确。 |
| ALIGN 结束依赖传感器零位捕获。 | 无感启动在 ALIGN 到期后直接进入 RUN。 | 修复了无感启动使用原捕获流程时会失败的路径；基线并非所有 ALIGN 都故障。 |
| Position 直接输出选定来源。 | 增加资格窗口、BLEND、OBSERVER/FAILED 与事件。 | 交接状态有必要；SMO 专属判据目前与选角逻辑耦合。 |

## 2. 有代码依据的问题

### 2.1 强拖期限重复，建议由 Motor 统一保护

[`motor.c`](../motor/motor.c#L313) 用 `wSensorlessRunSteps/wStartupMaxRunSteps` 限制电流模式运行时间；[`motor_position.c`](../motor/motor_position.c#L257) 又用 `wForcedCount/wMaxForcedSteps` 限制等待接管的时间。两个上限默认都是 60000 步，但可独立配置，先触发哪一路取决于配置与 ISR 顺序。这是重复状态，并非随机故障。

建议由 Motor 维护**一个启动总期限**，在未完成接管时超时安全停机；Position 只维护资格计数、融合进度和观测器失效状态。删除 Position 的期限后，仍须保留必要校验：总期限应覆盖斜坡、资格窗口和融合可能达到的实际时长。不能仅删除 [`foc_app.c`](../app/foc_app.c#L375) 的跨参数检查而不建立新的边界。

### 2.2 `wBlendSteps` 是最短条件，不是融合耗时上界

[`motor_position.c`](../motor/motor_position.c#L109) 同时使用按 `wBlendSteps` 增长的速度权重，以及每拍最多约 0.5 电角度的角度修正。只有权重完成且本拍能修完剩余角差，状态才变为 OBSERVER。因此配置为 4 步不代表第 4 步必然完成；角差以及两路角度的持续变化都会影响实际耗时。

建议明确 `wBlendSteps` 的语义，给融合阶段设置可验证的时间上界，并在总启动期限内处理超时。测试应使用逐拍变化的两路角度，检查控制角连续性、反馈速度、完成时间和超时后的安全输出。现有[接管测试](../tests/sensorless_position_handoff_test.c#L74)允许循环至 100 拍，不能证明配置步数就是实际步数。

### 2.3 计划中的限幅/饱和资格输入尚未落实

计划 Task 3 要求资格器检查电流和电压限幅。当前[`motor_position_sample_t`](../motor/motor_position.h#L33)不携带限流或调制饱和状态；[`_motor_position_ObserverQualified()`](../motor/motor_position.c#L36)检查的是有效性、反电势强度、速度与角差。限幅期间资格计数因此仍可能增长。

启用自动接管前，应通过实测决定哪些限幅状态必须阻止接管，把所需状态明确传给资格判据并增加相应测试。若实验表明某项不必作为条件，应同步修改计划。不能仅凭当前判据或主机测试断言带载接管可靠。

### 2.4 两套强制角轨迹需要决定去留

[`motor.c`](../motor/motor.c#L335) 按 `bSensorlessStart` 选择旧定频累加器或 `motor_startup_IsrStep()`；两路都输出 `tHardDragCandidate`。旧路径仍被测试覆盖，且通过普通 `motor_Start()` 运行；新路径经 `motor_StartSensorlessSpeed()` 进行对齐和电流模式斜坡，行为不同。

若定频实验仍需保留，可让一个轨迹模块显式支持定频与斜坡两种配置，再逐步迁移调用者。若确实废弃定频实验，在确认外部用途后删去旧字段和分支。**`wRampSteps == 0` 目前不能直接表示定频**：[`motor_startup_Init()`](../motor/motor_startup.c#L16)拒绝零，`motor_startup_Start()`还以步数作除数。迁移设计须写明原有启动、对齐和速度模式语义是否保留。

### 2.5 接管配置转抄较多

接管默认值定义于[`motor_config.h`](../app/motor_config.h#L33)，再进入[`foc_app_cfg_t`](../app/foc_app.h#L31)、`motor_position_cfg_t`，最终复制到 `motor_position_t`。可用一个 Position 接管配置子结构体减少 App 的逐字段转抄，同时只在运行对象中保存实时路径需要的值和预计算结果。这不要求给每个字段增加 getter/setter。

## 3. 需要修正表述或先验证的判断

### 3.1 不能因“ISR 中有 64 位除法和 double”要求重写斜坡

[`motor_startup_Start()`](../motor/motor_startup.c#L30) 中的 `double`、`llround` 和按斜坡步数进行的 64 位除法发生在启动阶段。[`motor_startup_IsrStep()`](../motor/motor_startup.c#L76) 使用 64 位累加，并以常数 65536 换算；是否生成昂贵的除法指令，应看目标编译器输出或测最坏 ISR 时延。Q16 小数位使小加速度在长斜坡下仍可累加，直接改为 32 位 BAM 整数步长可能使增量量化为零。

若要简化数值实现，先给出最小目标速度、最长斜坡、每拍相位误差和最坏执行时间的界限，再比较 32 位与当前实现。`2^48` 应写成带单位的预计算公式或命名常量，提高可读性；目前没有证据要求删除所有 64 位运算。

### 3.2 45°角差门槛不能由载荷角公式直接判死

代码比较的是**强制 d 轴电角度**与**观测转子电角度**。若强制坐标系中的 `Id_ref=0`、`Iq_ref>0`，表贴式 PMSM 的近似电磁转矩随这两个 d 轴的角差变化，可写成 `T_e ≈ K·Iq·cos(Δθ)`；若把角度定义成定子电流矢量与转子磁链的夹角，才对应 `sin(δ)`。这两个角度定义不能混用；凸极效应、估算相位误差和动态过程还会改变关系。

[`qMaximumAngleErrorTurns`](../motor/motor_position.c#L67) 默认为 0.125 turns（45 电角度）。它可能妨碍某些负载下的资格累计，也可能是必要的失步保护；目前不能断言带载运行必超过 45°或必然超时。应在不同负载、加速度下记录强制角、编码器对照角、SMO 角与 `Iq/Vq`，据最差合格窗口确定门槛。

### 3.3 单拍清零是保守资格规则，不能直接改成漏桶

[`motor_position.c`](../motor/motor_position.c#L260) 在一次不合格时把连续资格计数清零。噪声可能影响接管机会，但连续合格 4000 拍也是有意设置的安全条件。固定的“合格 +1、不合格 −5”会允许周期性无效样本累积到接管，不能在没有波形和故障分类时视为改进。

先统计失败原因及持续长度，再区分必须立即清零的硬失效（例如方向错误、非有限值、明显失锁）和可容忍的短时质量波动。只有后者有证据时，才设计明确上限的去抖或迟滞，并测试反复失效不能通过资格。

### 3.4 固定阈值与速度 PI 冲击均需分开判断

滤速系数 0.02、每拍约 0.5 电角度纠偏和启动速度 0.8 pu 上限都有固定值，适用性需要台架数据。但[`motor_StartSensorlessSpeed()`](../motor/motor.c#L588)同时检查 0.8 pu 和外部 `qMaxSpeedReference`；0.8 pu 是额外安全上限，并未绕过配置。

[`motor_ApplyPositionEventIsr()`](../motor/motor.c#L973) 在切入速度模式前调用 `foc_pid_Track()`，并把速度参考置为当前观测速度，已有避免首拍输出跳变的措施。仍需验证首个速度环周期的 `Iq`、电角度、PWM 占空比及随后目标速度斜坡；“存在转矩冲击”目前是待验证风险，不是已确认缺陷。

## 4. 对其他融合算法的适用范围

`motor_electrical_feedback_t` 的最终输出边界可以继续使用，ISR 主链也值得保留。当前 Position 内部资格与状态专为**强拖 → SMO**编写：它读取 SMO 信号强度、原始速度，并以强制角为参照。换用磁链模型、EKF，或做 Encoder + SMO 融合，都需重新定义候选质量与选源策略；不要把现有判据视为通用合同。

HFI 还需要注入电压、同步采样、解调、极性判断和算法收敛。现有 20 kHz `iαβ` 样本不能单独证明某一载波频率可用，也不能保证上电第一拍就获得可闭环的角度。HFI 与 SMO 的交叠速度及迟滞范围应由电机参数、PWM/ADC 时序和台架数据决定。目前不预留注入钩子、置信度注册表或固定的 0.1/0.2 pu 融合区间；出现实际 HFI 需求时再设计执行链路。

## 5. 建议的整理顺序与验证条件

1. **先补证据：** 自动接管保持关闭；记录资格失败原因、角差、限幅状态、实际融合步数和最坏 ISR 时间。更新 [`foc-architecture.md`](foc-architecture.md) 中过时的选角与 Observer 更新顺序。
2. **再消除重复：** 将启动总期限归口 Motor，并重新校验配置或运行时超时边界；按定频实验的实际用途统一或删除旧轨迹。保留 PWM 安全停机和故障锁存。
3. **收拢配置：** 以子结构体传递接管配置；运行时只存必要参数。任何数值实现变更都用范围计算和最坏时延证据支撑。
4. **最后扩展来源：** 第二种估算器真实接入后，先做候选转换与专属资格判断；只有重复交接逻辑出现时才抽共用代码。

每一项代码变更都应覆盖 FLOAT/FIXED 主机边界与安全路径。自动接管的参数必须以多次台架实验定稿；本文不估算可删除的行数，也不宣称安全隐患已经消除。
