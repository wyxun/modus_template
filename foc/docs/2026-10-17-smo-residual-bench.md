# SMO 电流残差验证：局部结论成立，全流程验收未通过

本轮使用残差诊断固件，未改控制代码、算法参数或门槛，未烧录、复位、halt 或使用 GDB。电机最终已故障停机，PWM=0，自动接管配置恢复为开启。不能将本轮表述为“SMO 问题已解决”或“自动接管验证通过”。

## 本轮确定的结论

1. 完整强拖影子记录中，稳速段已采到的两轴残差均未达到 ±0.1 pu 的边界，不能据此认定当前问题主要来自频繁饱和切换。10 kHz 观测仍可能漏过 20 kHz 的单拍事件，结论只覆盖采到的点。
2. 残差主要为电角基波。在当前边界层线性区，非零残差是生成滑模电压/反电势估计的一部分，不能把这部分幅值直接解释成模型坏了，也不能以“残差必须为零”为目标盲目加增益。
3. 一些相对角差尖峰同时伴有编码器参考的反向/大幅增量；参考使用缓存年龄外推，因此相对角差尖峰不能全部归到 SMO。SMO 自身也存在波动，前轮直接捕获的 0.480 pu 速度越界依然成立。
4. 自动接管全流程采集多次出现丢样，正式完整性验收未通过。仅连续 RUN 片段可以限定用途分析，不能代替包含对齐、渐变失败和停机过程的完整验证。

- 两轴已采到点的 `abs(residual) >= 0.1 pu` 比例均为零。

## 为什么有基波残差并不等于模型失效

板上读取的执行系数为：

| 系数 | 地址 / 原始字 | 近似数值 |
|---|---|---:|
| ku | 0x20003A28 / 0x3E124923 | 0.1428571 |
| kr | 0x20003A2C / 0x3E2AAAAA | 0.1666667 |
| b0 | 0x20003A30 / 0x3DBA2E8B | 0.0909091 |
| a1 | 0x20003A34 / 0xBF51745C | -0.8181818 |
| h | 0x20003A38 / 0x3ED55555 | 0.4166667 |
| boundary_gain | 0x20003A3C / 0x40855555 | 4.1666665 |

当前配置为 R=4000 mΩ、Ld=Lq=1200 μH、滑模电压 5000 mV、边界半宽 0.1 pu、反电势滤波截止 4000 rad/s。

线性区内 `z = G * (i_hat - i_measured)`，所以显示残差的反号乘 G 才是滑模电压。非零反电势对应非零残差是该结构本身的性质。残差基波约 0.053 pu、G≈4.167，对应 z 基波约 0.22 电压 pu，与前轮反电势同量级；这是内部一致性解释，不是独立的模型精度证明。

只读检查还给出一个有限的离散稳定性结果：在不冻结、不饱和的局部均匀模型下，令 `a=kr+ku*G≈0.7619046`，当前电流估计递推的特征多项式为：

`λ² - (1-a/2)λ + a/2 = 0`

其极点约为 0.309524±0.533992j，模约 0.617213。没有据此发现名义线性内部递推失稳；这不证明耦合电机闭环稳定，也不覆盖参数失配、输入时序误差、限幅及未采到的单拍扰动。不能以此为理由任意提高增益。

## 自动渐变的局部观察

C 的连续 RUN 片段中，故障前约 190 ms 的残差矢量 RMS 为 0.053634 pu，拟合去除常量/基波后的 RMS 为 0.009224 pu，与完整强拖记录同量级。

最后 4 ms 已采到的两轴残差范围约为：α [-0.059,0.052] pu、β [-0.059,0.053] pu，均未达到 ±0.1。没有看到明显撞边界或残差幅值爆发，但这不足以确认未采到的单拍行为。

C 渐变计数为 63，约 3.15 ms，小于 160 电 Hz 的一个电周期 6.25 ms。不能用这么短的渐变段可靠比较基波参数、谐波谱或统计噪声改善。相对角差仍有波动，当前四路没有同时记录实际速度、反电势和电压输入，不能精确恢复所有失败谓词。

## 参考角度需要单独验证

完整强拖稳速段的相邻 100 μs 电角增量：

| 来源 | P1 | 中位 | P99 | 标准差 | 反向增量点数 |
|---|---:|---:|---:|---:|---:|
| SMO | 2.516° | 5.760° | 9.360° | 1.448° | 0 |
| EncAbs | 0.720° | 5.760° | 10.080° | 1.109° | 60 |

两者都存在波动。自动 C 局部的一些相对角差尖峰处，SMO 增量约 4.68～6.84°，而 EncAbs 为 -1.80°、-0.72° 或 11.52°。这提示参考更新/外推对尖峰有贡献，但不证明全部波动都来自编码器，也不能推翻前轮直接记录到的 SMO 速度越界。

代码对应机制已只读确认：`foc_encoder_Run()` 在传感器读取返回后记录完成时间戳；`foc_encoder_GetPosition()` 用缓存速度乘样本年龄外推。新缓存发布后，预测轨迹由新角度接替。采样完成时间、实际传感器角度时刻、滤波速度和前台读取耗时的差异，可能造成更新跳变，尚未量出各自贡献。

因此，基于 EncAbs 拟合的“非基波残差”和相对角差尖峰不能直接作为纯 SMO 噪声指标。必须先验证参考的时间对齐，不能把数据磨平来代替这一验证。

## 采集链路排查及未通过项

用户已关闭 mstudio，单连接仍出现问题，故没有证据将 mstudio 认定为唯一根因。

工具文档明确：无客户端时 OpenOCD 不抽取 RTT，固件队列会丢样。停机单连接记录出现很大的历史样本缺口，但稳定尾段 5000 点连续，说明开始积压与稳定采集必须分开验收。

曾尝试第二个 AITrace 读进程维持排空，停机测试反而出现样本序号回退，该办法已弃用，读进程已结束，期间未启动电机。不据此断言 OpenOCD 多客户端实现必然有错；它只是本会话未通过的测试方法。

随后采用单连接、2 s 预读、MCU 样本序号标记正式起止，仍未通过全试验区间完整性检查。C 的故障前 RUN 段可连续提取，但正式起止范围有空行、缺口及设备计数增长。不能靠裁剪自动宣布整体通过。

当前 Makefile 实际设为 `rtt polling_interval 1`，与工具手册旧的 10 ms 说明不同；未凭旧手册再盲目修改轮询间隔。RTT full 是传输链路证据，不等价于 ADC 或 FOC 丢拍证据，根因仍需查明。

## 20 kHz 耗时及安全界限

本轮抽查最大值：shadow 45.2529 μs；auto A 43.8882 μs；auto B 46.3824 μs；auto C 43.8882 μs。最高 46.3824 μs 距 50 μs 约余 3.6176 μs，未读到超过本轮 47 μs 主机提前停止阈值的值。

这些是间歇读取计时窗口最大值，不是 WCET；波形判废不使独立 shell 计时读数无效，但也不能用这些读数覆盖没有读取到的窗口。当前计时测的是 ISR 执行时长，未独立验证 ISR 入口间隔、触发漏计或前台临界区引起的延迟。不能据此宣布整个 20 kHz 实时性验证通过。
