
# FOC 模块架构与实时数据流

## 1. 顶层数据流

一个可验证的 FOC 系统至少要能画出以下链路：

```text
PWM trigger
  -> ADC sample / DMA
  -> current offset and scaling
  -> Clarke / Park
  -> angle and speed observer
  -> speed loop / flux weakening / MTPA
  -> current loop and decoupling
  -> inverse Park / SVPWM
  -> compare-register update
  -> next PWM effective point
```

编码器路径可以替换观测器输入，但不能省略采样、变换、环路和调制之间的时序关系。每个箭头都应能回答：数据单位是什么、在哪个中断执行、使用当前拍还是上一拍、谁拥有状态、失败时如何安全退出。

## 2. 推荐模块边界

| 模块 | 主要输入 | 主要输出 | 频率/状态 | 首要验证 |
|---|---|---|---|---|
| 配置与基值 | 电机、母线、限幅、PU 基值 | 只读配置快照 | 初始化/低频 | 单位、范围、版本 |
| PWM/ADC 采集 | 触发、ADC、DMA | 原始三相样本、母线 | 快速环 | 时序、偏置、极性 |
| 坐标变换 | 三相电流、角度 | alpha-beta、d-q 电流 | 快速环 | 静止输入和能量守恒 |
| 角度/速度 | 电流、电压、参数、编码器 | 角度、速度、有效标志 | 快速环 | 与编码器误差 |
| 电流环 | `Id/Iq` 参考和反馈 | `Ud/Uq` | 快速环 | 阶跃、带宽、饱和 |
| 速度环 | 速度参考和反馈 | `Iq` 或转矩参考 | 慢环 | 加减速、负载阶跃 |
| MTPA/弱磁 | 转速、电压、电流限制 | `Id`、`Iq` 限制 | 慢环/查表 | 圆/椭圆约束 |
| 解耦/前馈 | 速度、电流、参数 | 补偿电压 | 快速环 | 高速电流误差 |
| 逆变器调制 | dq 电压、母线 | 三相比较值 | 快速环 | 占空比、过调制、死区 |
| 启动/切换 | 状态、速度、观测有效性 | 控制模式和参考 | 状态机 | 超时、失步、安全停机 |
| 参数辨识 | 激励、采样、状态 | 参数和置信度 | 专用流程 | 重复性、边界 |
| 保护/诊断 | 电流、母线、温度、状态 | 故障锁存、安全输出 | 快速/慢速 | 故障收敛和可观测性 |

模块应通过有单位和范围的类型或明确命名的结构体传递数据。不要用没有语义的 `void *`、混合单位字段或隐藏全局变量连接实时模块。

## 3. 快速环与慢速环

以单周期采样、单周期更新为例：

1. 定时器触发 ADC；
2. ADC/DMA 完成中断取得样本；
3. 读取并扣除电流偏置，换算到算法量程；
4. 执行 Clarke/Park；
5. 执行编码器或观测器、PLL 和角度补偿；
6. 执行电流环、解耦和电压限幅；
7. 反 Park、SVPWM、死区/过调制处理；
8. 在下次采样前写入比较值。

速度环、弱磁、MTPA、统计和低频诊断可以降频执行，但必须把实际执行周期传给积分器、滤波器和限幅计算。不要因为函数名叫 `speed_loop` 就假定它与 PWM 同频。

快速环必须有界、无阻塞、无总线等待、无高频日志，并且能够在故障时快速把输出置于安全状态。观测器、变换和调制的计算开销要放在同一个时序预算内，不能只测 PI 函数本身。

## 4. 各模块的设计契约

每个 FOC 模块在设计文档中至少写清：

- 输入变量、输出变量和物理单位；
- 参考方向、坐标系、峰值/RMS 和正负号；
- 执行频率、采样点、输入是当前拍还是上一拍；
- 可变状态、初始化值、复位动作和所有权；
- 限幅、饱和、除零、溢出和无效输入处理；
- 正常、降级、故障和安全停机状态；
- 浮点、PU、定点三种实现的等价性测试；
- 可观测波形和离线复现入口。

这样做的目的是让模块可以先在 Simulink/Python 中独立验证，再移植到 C；不是为了强行建立一套复杂的软件框架。

## 5. 观测器和启动切换

编码器、磁链模型、PLL、SMO、Active Flux、高频注入和 I-f 都是不同的角度信息来源。把它们组合时需要定义：

- 谁产生角度，谁产生速度，谁拥有滤波器状态；
- 角度有效的判据、收敛时间和失效动作；
- 观测器角度与电流环使用角度之间的补偿；
- I-f、零电流、反电势或高频注入到 FOC 的切换条件；
- 切换时电流参考、相位、积分器和限幅如何连续。

不能只看观测器内部波形“看起来稳定”就宣称角度准确。至少要与编码器、输出功率或同负载下的性能对比。

## 6. 保护、诊断和可观测性

保护不是事后加的日志模块。架构阶段就要确定：

- 过流、过压、欠压、过温、失步和采样无效的优先级；
- 故障锁存在哪个对象中，如何进入安全输出，何时允许复位；
- 低频事件日志与周期性波形统计分开；
- 不在硬实时 ISR 中打印、访问总线或执行不定时操作；
- 诊断数据应能重建一次控制周期的输入、状态、限幅和输出。

修改嵌入式实现时，使用项目的 `embedded-coding` Skill 审核对象所有权、状态机、实时调用深度和测试；本文件只定义控制域模块的职责和验证边界。
