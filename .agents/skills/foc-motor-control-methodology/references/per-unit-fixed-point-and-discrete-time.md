
# 标幺值、定点和离散时间

## 1. 标幺值的目的

标幺值不是为了隐藏单位，而是把不同功率、电压和速度等级的电机映射到同一套数值范围，降低中间计算溢出风险，方便仿真、定点实现和平台移植。每个标幺量都必须有明确基值，不能只把数值除以一个“看起来合适”的常数。

基本定义：

$$
x_{\mathrm{pu}}=\frac{x_{\mathrm{real}}}{x_{\mathrm{base}}},
\qquad
x_{\mathrm{real}}=x_{\mathrm{pu}}x_{\mathrm{base}}
$$

建议至少定义并记录：

$$
U_{\mathrm{base}},\ I_{\mathrm{base}},\ \omega_{\mathrm{base}},\
\Psi_{\mathrm{base}},\ T_{\mathrm{base}},\ t_{\mathrm{base}}
$$

常见且容易自洽的一组选择是：

$$
\begin{aligned}
R_{\mathrm{base}}&=\frac{U_{\mathrm{base}}}{I_{\mathrm{base}}},\\
L_{\mathrm{base}}&=\frac{U_{\mathrm{base}}}
{\omega_{\mathrm{base}}I_{\mathrm{base}}},\\
\Psi_{\mathrm{base}}&=\frac{U_{\mathrm{base}}}{\omega_{\mathrm{base}}},\\
t_{\mathrm{pu}}&=\frac{t_{\mathrm{real}}}{t_{\mathrm{base}}},\\
T_{s,\mathrm{pu}}&=\frac{T_{s,\mathrm{real}}}{t_{\mathrm{base}}}
\end{aligned}
$$

若以电角频率基值定义时间，通常取 `t_base = 1 / omega_base`，因此 `Ts_pu = omega_base * Ts_real`。也可以使用其他时间基，但必须从同一套定义推导所有积分和微分项。

转矩基值必须和转矩公式的归一化一致。例如在常见幅值不变约定下可从 `T_base = 3/2 * p * Psi_base * I_base` 推出；如果项目采用功率不变变换，比例因子应随项目公式变化。

## 2. dq 电压方程的标幺推导

从真实值模型开始：

$$
\begin{aligned}
u_d &= R_s i_d+L_d\frac{di_d}{dt}-\omega_e L_q i_q,\\
u_q &= R_s i_q+L_q\frac{di_q}{dt}
      +\omega_e(L_d i_d+\Psi_r)
\end{aligned}
$$

把每个量替换为 `x_real = x_pu * x_base`，再除以 `U_base`。由基值定义可得：

$$
\begin{aligned}
u_{d,\mathrm{pu}}={}&R_{s,\mathrm{pu}}i_{d,\mathrm{pu}}
 +L_{d,\mathrm{pu}}\frac{\Delta i_{d,\mathrm{pu}}}
 {T_{s,\mathrm{pu}}}
 -\omega_{e,\mathrm{pu}}L_{q,\mathrm{pu}}i_{q,\mathrm{pu}},\\
u_{q,\mathrm{pu}}={}&R_{s,\mathrm{pu}}i_{q,\mathrm{pu}}
 +L_{q,\mathrm{pu}}\frac{\Delta i_{q,\mathrm{pu}}}
 {T_{s,\mathrm{pu}}}
 +\omega_{e,\mathrm{pu}}
 (L_{d,\mathrm{pu}}i_{d,\mathrm{pu}}+\Psi_{r,\mathrm{pu}})
\end{aligned}
$$

这不是另一套物理模型；它必须在相同基值、相同采样周期和相同坐标约定下与真实值模型得到相同的波形。验证方法是同时运行真实值和 PU 模型，比较电流、速度、转矩和饱和点，而不是只比较某个中间变量。

## 3. 基值选择

基值的目标是给预期最大范围留出裕量，同时保留足够的定点分辨率：

- `I_base` 应覆盖正常最大相电流和瞬态余量，不能刚好等于额定值；
- `U_base` 应与模型使用的相电压定义一致，不能把线电压 RMS 直接当相电压峰值；
- `omega_base` 要说明是机械还是电角速度，并覆盖最高运行点；
- `Psi_base`、`T_base` 和时间基由前述方程推导，避免独立拍脑袋设置；
- 调整基值后，要重新检查所有限幅、PI 参数、查表轴和通信显示换算。

标幺值的优先级是“自洽和可验证”，不是追求所有量都恰好等于 1。若电机参数未知，可以用铭牌、功率平衡和低风险测量估算初值，再用实际波形修正。

## 4. Q 格式与定点实现

先在浮点或 Python/Simulink 中验证范围，再选择 Q 格式：

1. 列出每个输入、状态、中间乘积和输出的最大正负范围；
2. 为正常运行和瞬态各保留余量，不能把满量程当成可用量程；
3. 乘法先扩展到更宽类型，做显式缩放和饱和，再缩回目标 Q 格式；
4. 所有除法检查除数为零或接近零；
5. 对积分器、角度累加器、速度和观测器状态分别检查溢出；
6. 用真实值、PU 和定点三套仿真结果交叉比较。

定点实现的常见故障不是“算法不对”，而是移位、符号扩展、乘积宽度或限幅顺序错误。溢出导致的极性翻转尤其容易伪装成坐标、极性或观测器问题。

## 5. 离散滤波器

一阶低通可以按连续截止角频率 `omega_c` 和执行周期 `Ts` 推导：

$$
\begin{aligned}
a&=\frac{1}{1+\omega_cT_s},\\
b&=\frac{\omega_cT_s}{1+\omega_cT_s},\\
y[n]&=a\,y[n-1]+b\,x[n]
\end{aligned}
$$

定点化时把 `a`、`b` 映射到同一 Q 格式，检查量化后 `a+b` 是否仍接近该格式的 1。`Ts` 是滤波器实际执行间隔，不是输入信号刷新间隔；如果速度环比电流环慢，必须使用速度环的执行周期。

量化误差、截止频率、相位滞后和状态初值都要在仿真中检查。不要只替换两个系数就假定滤波器行为不变。

## 6. PWM 更新延时和角度补偿

使用影子寄存器时，本周期计算的比较值可能在下一周期才生效。因此“当前采样的电流”和“当前计算的电压”并不一定属于同一电角度。补偿前先画出：

```text
ADC trigger -> DMA complete -> FOC calculation -> CCR write -> PWM effective
```

要分别审计以下角度用途：

- 电流坐标变换角度；
- 电压重构/观测器使用的电压角度；
- 电流重构角度；
- 上一拍电压角度；
- 电流环反变换和 SVPWM 使用的角度。

不同硬件和计数方式可能对应 `Ts`、`1.5Ts` 或其他延时。课件中的 `1Ts/1.5Ts` 是分析起点，不是固定补偿常数。通常电压重构角度对高速无感性能更敏感，但必须用实际更新点和仿真波形决定补偿极性与幅值。

## 7. 不要混淆这些频率

分别记录并命名：

| 量 | 含义 |
|---|---|
| PWM/开关频率 | 功率器件或调制周期频率 |
| ADC 采样频率 | 采样触发和有效样本产生频率 |
| FOC 计算频率 | 快速控制算法执行频率 |
| 电流/电气频率 | 电机电流或电角度变化频率 |
| 电流环带宽 | 闭环对电流参考的动态响应 |
| 速度环带宽 | 外环对速度参考的动态响应 |

例如 `20 kHz` 的 PWM、采样和 FOC 计算，不等于电流频率 `300 Hz`，也不等于电流环带宽 `500 Hz`。所有带宽公式必须使用对应环路的执行周期。

## 8. 本仓库算法模板：边界、公式和数值表达

本节解释 `embedded-coding` L1.9 的实现选择，沿用前文的标幺体系，不重新定义模型。现有源码可能存在未完成的边界整理；本节是后续优化目标，不能据此宣称现有接口均为 pu。

### 8.1 物理边界与初始化

| 边界 | 外部表示 | 内部表示与责任 |
|---|---|---|
| 电流采样 | 三相 ADC 原始码 | Motor 扣每相实测零偏，按标定增益及电流基值转换为宽电流 pu；不隐式裁到 ±1，表达范围错误必须报告 |
| 母线采样 | Motor 直接 API 读取原始 ADC 码 | Motor 按板级 ADC 标定归一化为 `vbus_pu`，在 Prepare 中重构共享前区间模型；App 只消费快照 |
| 电机参数 | 相电阻、电感、磁链等物理值 | 初始化形成标幺模型，算法初始化生成自身离散系数 |
| 指令入口 | A、rpm 等物理指令 | 指令入口转换为参考 pu；机械转速转换包含极对数 |
| 调制输出 | 电压 pu、母线 pu | 调制求归一化占空比，硬件端口再转换为定时器计数 |
| 显示出口 | 算法 pu | 显示/诊断按需转换为物理量，不反馈给控制 |

频率基值若按电角 Hz 配置，则 `omega_base = 2*pi*f_base`。速度 pu 满足 `omega_e/omega_base = f_e/f_base`，不能直接用有量纲 Hz 代替。角度采用 `foc_angle_t` 的周期表示；角度圈数与速度 pu 不共用同一个基值含义。

初始化的数据推导是“物理参数 → 标幺模型 → 离散系数”，不是要求建立三层包装或保存三份参数。稳定换算可以代数合并，例如直接计算与标幺推导等价的 SMO `ku`、`kr`；共享模型只保存实际消费者需要的字段。算法每拍不再做 Ω/H、mV/mA 与 pu 的往返换算。辨识结果进入模型时，在安全更新点执行同样的归一化和系数更新，避免新旧系数混用。

固定电压基值下，电压 pu 不是占空比；调制需使用实时母线 pu，并维护电压定义、限幅及母线无效处理。`1 pu` 是基准而非通用限幅，实际上限由电机、逆变器及数值范围分别确定。

### 8.2 公共数值语言与特殊存储

标幺定义决定数值的物理意义，Q 格式决定存储缩放。公共标量采用 `foc_scalar_t`，公共角度采用 `foc_angle_t`。模块可以局部使用宽乘积或更精细的累加状态，但必须给出范围/分辨率依据，并在状态定义处写出“存储整数 = 所表示数值 × 缩放因子”。

例如启动模块的 `StepQ16` 当前表示“每拍 BAM32 增量附加 16 位小数”，并非普通角度 pu 的 Q16：

$$
step_{stored}=speed_{pu}\frac{f_b}{f_s}2^{32}2^{16}
$$

速度内部 Q31 存储则为 `speed_stored = speed_pu * 2^31`，载体可以是 `int64_t`；不能仅从 Q31 名称推断载体位宽或有效范围。这类状态应明确单位、缩放、截断/舍入、正负处理和溢出边界，输出恢复公共格式。若同时累计速度和角度步进，需核对轨迹一致性和各自截断误差；没有证据不机械合并或删除。

禁止重复物理换算，不等于禁止必要的数值格式缩放。浮点公式可直接使用运算符；定点宽乘、饱和及舍入必须保持可见。两种后端共用公式和契约，允许必要的实现差异，不增加宏语言来隐藏差异。

### 8.3 数学命名与 SMO 阅读模板

| 名称示例 | 含义和适用位置 |
|---|---|
| `Rs`、`Ls`、`Ts`、`wc` | 物理参数入口或推导；明确 Ω、H、s、rad/s |
| `r`、`l`、`dt` | 算法初始化中的标幺电阻、电感和时间步长；注明基值 |
| `i`、`u` | 单轴输入电流和对应前一控制区间的模型电压，均为 pu |
| `i_hat`、`e_hat`、`z_prev` | 算法实例内部的估计值和历史切换量 |
| `err`、`z`、`di` | 范围小且意义明确的局部误差、切换量、电流增量 |
| `ku`、`kr`、`b0`、`a1` | 初始化生成的离散系数，定义旁写出公式 |

短名用于可直接对照公式的作用域，不用于模糊边界单位，也不使用 `part0/part1` 等无意义编号。公式、符号定义和拍关系是必要的算法说明，不属于机械注释。

对当前等电感 SMO，设 `dt = omega_base * Ts`，`r = Rs/R_base`，`l = Ls/L_base`，`p = wc*Ts`，初始化得到：

$$
ku=\frac{dt}{l},\quad kr=\frac{r\,dt}{l},\quad
b_0=\frac{p}{2+p},\quad a_1=\frac{p-2}{2+p}
$$

以下是在未触发限幅、冻结或数值饱和时，当前实现的单轴递推关系；`d` 是已经包含时间步长的电流增量输入，不是有量纲的电流导数：

$$
\begin{aligned}
d_k &= ku\,u_k-kr\,\hat i_{k-1}-ku\,z_{k-1},\\
\hat i_k &= \hat i_{k-1}+\tfrac12(d_k+d_{k-1}),\\
err_k &= \hat i_k-i_k,\\
z_k &= h\,\operatorname{sign}(err_k),\\
\hat e_k &= b_0(z_k+z_{k-1})-a_1\hat e_{k-1}.
\end{aligned}
$$

`h` 是滑模切换电压 pu。源码按“模型增量 → 积分与限幅/冻结 → 切换量 → 反电势滤波 → 历史更新”展开，限制和异常处理就近保留；使用旧历史后才更新它，不提前覆盖 `z_prev` 或增量历史。角度、速度输出紧随其后表达独立的公式步骤，不为每个乘加拆函数。

当前电流模型使用上一拍切换量 `z`，不是滤波后的 `e_hat`。把反馈改成 `e_hat`、加入凸极耦合项、替换积分器/滤波器、改变冻结解除时刻，都属于算法行为变更，不能作为命名或可读性优化顺便实施。

### 8.4 优化顺序与验收证据

先从 SMO 建立模板：列出现有输入输出、基值、状态、采样拍和转换位置；收窄依赖，整理初始化及核心公式，保留必要的数值保护。模板确认后再推广到 PLL、PI、滤波器，不同时重构整条控制链。

验收时，读核心函数应能逐项对照公式；读头文件应能确定单位、状态归属及时间关系；热路径不包含父对象、硬件、日志等无关依赖。用相同输入序列比较整理前后的逐拍输出、历史状态、限幅、冻结、复位和异常行为：定点保持一致；浮点预先定义误差容限并单独检查边界，不能仅因波形相似就宣称等价。初始化错误、零反电势、正反向及低速情况按改动涉及的风险覆盖。

性能改进以目标构建、代码生成或时序测量为证据。局部变量可用于清楚表达公式，不复制整个状态对象；不凭函数短、inline 或 FMA 就宣称执行更快。

### 8.5 当前初始化频率的存储约定

`qElectricalSpeedBaseHz` 在 App、Motor、Position、SMO 配置中统一表示物理电频率基值 Hz，仅初始化消费，不能直接当作速度 pu。FLOAT 存 Hz；FIXED 的 `int32_t` 存 `Hz × 32768`（15 位小数，载体不是 16 位 Q1.15）。配置范围取 `0 < Hz <= 65535`，常量经 `FOC_SCALAR()` 按最近值、半值远离零舍入；该宏不饱和，编码前必须保证范围，不能先溢出再指望 Init 校验恢复。初始化解码或直接推导归一化系数，Step 的速度仍为 pu。

应用配置宏 `MOTOR_CONFIG_MAX_SPEED_ELECTRICAL_HZ` 和 `MOTOR_CONFIG_SPEED_PI_*_PER_ELECTRICAL_HZ` 明确采用电 Hz / 每电 Hz 口径。App 的绑定适配器分别除以 / 乘以频率基值，形成 Motor 的速度 pu 限值和 pu PI 增益；热路径不得重复这一物理换算。现有 App 的嵌套配置结构仍复用 `motor_cfg_t` 承载绑定前值，须结合该适配约定阅读；直接调用 `motor_Init()` 时传入已经绑定的 pu 参数，不能照抄 App 的原始嵌套配置。

当前 Core 的电压字段实际为调制度命令，尚未改成物理电压 PU 输出；Motor 已通过占空比和实测母线重构统一理想模型供 Observer/Identify 使用。不要把调制度直接送入算法冒充电压 PU。电流坐标变换使用宽乘法，以免 FIXED 的 `foc_mul_pu()` 隐式限制输入到 ±1；所有显式算法限幅仍由各自模型定义。
